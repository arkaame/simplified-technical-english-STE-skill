# Simplified Technical English (ASD-STE100 Issue 9)

Write and rewrite technical documentation so a reader with limited English can understand it on the first pass. Follow ASD-STE100 Issue 9 writing rules. This skill is a writing aid. It is not the official standard and does not replace the official STE dictionary.

When the user has a company glossary, use those technical nouns and technical verbs. When they do not, use the categories in `references/technical-terms.md`.

## When this skill applies

- Draft a procedure, description, warning, caution, note, or manual topic in STE
- Convert existing English into STE
- Review text and list STE rule violations
- Choose approved words, technical nouns, or technical verbs
- Count words for the 20-word / 25-word limits

If the user wants marketing copy, narrative prose, or legal argument that is not technical documentation, do not force STE unless they ask.

## How to work

1. Identify the text type — procedure, description, safety instruction, or note.
2. Keep the technical meaning. Do not invent data, limits, part numbers, or risks.
3. Apply the rules in this order:
   - Words and part of speech (Section 1)
   - Multi-word nouns (Section 2)
   - Verb forms and voice (Section 3)
   - Sentence shape (Section 4)
   - Type-specific rules (Sections 5, 6, or 7)
   - Punctuation and word count (Section 8)
   - Construction and consistency (Section 9 and GR-1 thru GR-8)
4. Replace unapproved words. Use `references/substitutions.md` first. If a replacement would change meaning, write a different sentence.
5. Count words with the Section 8 method. Split sentences that are too long.
6. Return the STE text. If the user asked for a review, also list violations by rule number.

Read `references/rules.md` when a rule needs more detail. Read `references/checklist.md` before you deliver.

## What you may use

Use only:

- Words approved in the STE dictionary, in the approved part of speech and approved meaning
- Technical nouns that fit a Rule 1.5 category
- Technical verbs that fit a Rule 1.12 category, and only when no approved dictionary verb gives the same meaning
- Quoted text (placards, labels, display legends, official titles) unchanged

Do not use a dictionary word as a different part of speech. Example — TEST is a noun, not a verb. Write `Do a test of the system`, not `Test the system` unless TEST is an official label.

Prefer an approved verb plus a technical noun over a technical verb. Example — write `Apply grease to the fasteners`, not `Grease the fasteners`.

## Hard limits

Procedures, warnings, and cautions — maximum 20 words in each sentence. Use the imperative. Write one instruction per sentence unless two actions occur at the same time.

Descriptive sentences — maximum 25 words. Use the active voice. Use the passive only if the agent is unknown. Do not use the imperative.

Notes in a procedure — information only, no imperative, maximum 25 words.

Count each of these as one word — a number, a number plus unit (6 mm), an abbreviation, an alphanumeric identifier, quoted text, a title or placard, a proper noun of a person, group, organization, or country, a hyphenated word, and text in parentheses (the parenthetical also counts as its own sentence).

A colon that starts a vertical list ends the first sentence for word count. Each list item is a new sentence.

## All 53 rules (Issue 9)

### Section 1 — Words

- 1.1 Use approved dictionary words, technical nouns, or technical verbs.
- 1.2 Use an approved word only as the specified part of speech.
- 1.3 Use an approved word only with its approved meaning.
- 1.4 Use only the approved forms of verbs and adjectives.
- 1.5 You can use a word that fits a technical noun category.
- 1.6 Use a word that is not approved only when it is a technical noun or part of one.
- 1.7 Do not use a technical noun as a verb.
- 1.8 Use technical nouns approved in the company, industry, or subject field.
- 1.9 When you select a technical noun, use one that is short and easy to understand.
- 1.10 Do not use regional, slang, or jargon words as technical nouns.
- 1.11 Do not use different technical nouns for the same item.
- 1.12 You can use a verb that fits a technical verb category.
- 1.13 Do not use a technical verb as a noun.
- 1.14 Use American English spelling unless an official directive says differently.

### Section 2 — Multi-word nouns

- 2.1 Write multi-word nouns of no more than three words.
- 2.2 If a technical noun has more than three words, write it in full first. Then give a shorter form, or use hyphens to show words that operate as one unit.

### Section 3 — Verbs

- 3.1 Use only the verb forms given in the dictionary.
- 3.2 Use only these forms — infinitive, imperative, simple present, simple past, simple future, past participle as an adjective.
- 3.3 Use the past participle as an adjective.
- 3.4 Do not use auxiliary verbs to make complex verb constructions (no continuous, perfect, or modal stacks such as should have been).
- 3.5 Use the -ing form only as a technical noun or as a modifier in a technical noun.
- 3.6 Use the active voice. In descriptive writing, use the passive only when the agent is unknown.
- 3.7 Use an approved verb to describe an action, not a noun or other part of speech.

Permitted — Remove the cover. / The pump supplies pressure. / The valve will close. / the disconnected hose

Not permitted — is removing, has removed, should be removed, to be removed, removal of the unit when remove can do the work.

### Section 4 — Sentences

- 4.1 Write short and clear sentences.
- 4.2 Do not omit words or use contractions (don't, it's, can't).
- 4.3 Use a vertical list for complex texts.
- 4.4 Use connecting words and phrases to connect related sentences (and, but, then, thus, as a result, at the same time).
- 4.5 When applicable, put the, a, an, this, or these before a noun or multi-word noun.

### Section 5 — Procedural writing

- 5.1 Maximum 20 words in each sentence (also for warnings and cautions).
- 5.2 One instruction per sentence unless two or more actions occur at the same time.
- 5.3 Write instructions in the imperative.
- 5.4 Put the condition first, then a comma, then the command. When the light comes on, set the switch to NORMAL.
- 5.5 Notes give information, not instructions. No imperative in a note. Notes use the 25-word descriptive limit.

Do not write you must before an ordinary command. Use must only for an important safety condition.

### Section 6 — Descriptive writing

- 6.1 Give information gradually.
- 6.2 Use key words and key phrases to give the text a logical structure.
- 6.3 Maximum 25 words in each sentence.
- 6.4 Use paragraphs to show related information.
- 6.5 Each paragraph has only one topic.
- 6.6 No paragraph has more than six sentences.

Do not use the imperative in descriptive writing.

### Section 7 — Safety instructions

- 7.1 Identify the risk level with an applicable word such as WARNING or CAUTION.
- 7.2 Start with a clear command or condition.
- 7.3 Explain the risk or possible result.

WARNING — risk of injury or death. CAUTION — risk of damage to equipment. If both risks exist, use WARNING.

Write the command, then the result.

### Section 8 — Punctuation and word count

- 8.1 You can use standard English punctuation except the semicolon.
- 8.2 Use hyphens to connect words that are directly related.
- 8.3 Use parentheses for figure/item callouts, step numbers, abbreviations, singular/plural (s), short explanations, and alternatives.
- 8.4 In a vertical list, a colon counts as a period.
- 8.5 Text in parentheses counts as one word in the outer sentence and as its own sentence internally.
- 8.6 Count numbers, number+unit, abbreviations, identifiers, quoted text, titles/placards, and proper nouns as one word each.
- 8.7 Hyphenated words count as one word.

Write thru for inclusive ranges (steps 13 thru 16). Do not use a semicolon to join clauses. Split the sentence or use a period.

### Section 9 — Writing practices

- 9.1 When a word-for-word replacement is not sufficient, write a different sentence that keeps the meaning.
- 9.2 Use each approved word correctly.
- 9.3 When you use two words together, do not make phrasal verbs that are not approved (carry out becomes do).
- 9.4 Use a consistent style. Same item, same noun. Same action, same wording.

### General recommendations (not rules)

- GR-1 Keep that after verbs such as make sure, show, recommend.
- GR-2 Reread every with. If it can mean has, together with, or by means of, rewrite.
- GR-3 If a pronoun can attach to more than one noun, repeat the noun. Do not use he or she.
- GR-4 Do not let this point at a whole clause when the target is not obvious.
- GR-5 Do not trust look-alike words from another language.
- GR-6 Do not use Latin abbreviations (e.g., i.e., etc.). Write for example, that is, or list the items.
- GR-7 Use inclusive, gender-neutral language.
- GR-8 The possessive 's is permitted but easy to misread. Prefer instructions from the manufacturer if the possessive is not clear.

## Output formats

**Write or convert (default).** Return only the STE text unless the user also wants a change list.

**Review.** Return:

1. STE rewrite
2. Findings — location, non-STE wording, rule, fix
3. Word-count flags for any sentence over the limit

**File mode.** When the user names a file, run the full process and write only the final STE text to that file. Change prose only. Keep code blocks, inline code, commands, paths, YAML metadata, data, part numbers, figure callouts, and link targets unchanged. Then give a short summary.

**Embedded mode.** When another task uses this skill inside a larger job, return only the STE text.

**Partial glossary.** If the user asks which words are technical nouns or verbs, name the category from `references/technical-terms.md`.

Keep part numbers, figure callouts, official names, and quoted legends exactly as given.

Do not invent a torque, limit, part number, temperature, or other value. If the source does not give a number, do not add one.

Do not add a specification the source did not state. If the source says `Tighten the bolts` and does not mention torque, write `Tighten the bolts.` Then ask for the torque if a limit is necessary. Write `the specified torque` only when the source already refers to a specification.
